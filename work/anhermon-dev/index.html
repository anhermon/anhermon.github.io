BeforeAfter
  1. Headline. v1 described the service in eight words ("AI agent pipelines you can observe and reproduce."). v4 states the problem in seven ("Agents that fail should leave a trace.") and puts what I do on the line below it.
  2. First screen. v1 was text and one button on flat navy, with no image. v4 opens on a drawn trace of light strands from an illustrative 8-span run, with a replay control, so the subject is visible before any copy is read.
  3. Navigation. v1 had four text links of equal weight (What I do, Public work, Engagement, Contact). v4 has three section links and Contact as the one filled button.
  4. Body. v1 was three card grids (what I do, public work) and a text list. v4 sets the problem as a short list of log lines, a live allowlist demo, and the repositories as a ruled ledger with their limits.
  5. The cost. Lighthouse mobile, simulated, both builds served from this machine on 2026-10-04: v1 scored 100 with LCP 0.9 s and 231 KB; v4 scored 96 with LCP 1.9 s and 448 KB. The hero image and WebGL layer make v4 heavier and slower. Both scored 100 on accessibility.

What was built

Art direction and sign-off: Angel. Design iteration, build, QA captures and Lighthouse runs: AI-agent pipeline.

A full front-page rebuild: v1 was a text-and-cards page with a describing headline and no imagery. v4 leads with a claim, a drawn trace as the hero, a live allowlist demo and a retyped system measured against ten reference sites.

  • Dark single-page site with a WebGL hero (light strands drawn from an illustrative 8-span run) and a static fallback
  • A replay control that re-draws the same strands, same seed, same frame
  • An allowlist demo using the real paths from an open-source MCP server
  • Lead form and double opt-in notes signup posting to a small Cloudflare backend, with honeypot and custom accessible checkbox
  • IntersectionObserver reveals (iOS Safari has no scroll-driven CSS)

Stack Static HTML, CSS, vanilla JS, WebGL, Inter variable (opsz), GitHub Pages

Interaction

Signature: the proof is live, not pictured

The Guard section runs real requests against the real 15-path allowlist from spark-ordernet-mcp, one every couple of seconds while in view: a POST is rejected, a near-miss spelling is rejected, the exact path passes. Timing is labelled illustrative.

How it was started Ten reference sites (including Stripe, Linear, Vercel, Notion, Figma, Apple, GOV.UK) were measured for type scale, spacing, tracking and radius; v4's numbers come from that table, not from taste.
